## ⑤ 备料与导入（你做）

### 5.1 目录规范

花园资产**全部**进 `Content/Env/Garden/`，不得写进 `Resources/`：

```
Content/Env/Garden/
├── Meshes/
│   ├── Structural/    墙、柱、拱、门楼
│   ├── Ground/        铺装、台阶、路缘
│   ├── Props/         亭、椅、灯、花坛
│   └── Foliage/       树、灌木、草、花
├── Materials/         M_Garden_* 母材质 与 MI_Garden_* 实例
├── Textures/          T_Garden_*
├── Foliage/           GF_Garden_* 植被类型
├── Decals/            D_Garden_*
├── FX/                NS_Garden_*
└── Blueprints/        BP_Garden_*
```

### 5.2 命名规范

| 前缀 | 类型 | 示例 |
|---|---|---|
| SM_ | StaticMesh | SM_Garden_Wall_Stone_A |
| M_ / MI_ | 材质 / 材质实例 | M_Garden_Stone；MI_Garden_Stone_Mossy |
| MF_ | 材质函数 | MF_Garden_Wetness |
| T_ | 贴图 | T_Garden_Stone_D |
| GF_ | 植被类型 | GF_Garden_Grass_Short |
| D_ | Decal 材质 | D_Garden_Moss |
| NS_ | Niagara 系统 | NS_Garden_Fountain |
| BP_ | 蓝图 | BP_Garden_Lamp |
| CF_ | 曲线 | CF_Garden_WindStrength |

**贴图后缀**：`_D` 基础色 / `_N` 法线 / `_ORM` 粗糙金属AO / `_H` 高度 / `_M` 遮罩

### 5.3 导入前自检（必须逐条过）

- [ ] 单位厘米（1m = 100uu），缩放 = 1.0（不烘焙缩放）
- [ ] Pivot 在**底部中心**（道具/植被）或**接缝处**（模块化件）
- [ ] 朝向 +X，Z 轴向上
- [ ] 模块化尺寸对齐网格（墙段 400/200，层高 300/400）
- [ ] 简单碰撞（盒/胶囊/凸包）；植被**不生成碰撞**
- [ ] LOD ≥ 4 级，或启用 Nanite（注意：遮罩植被用 Nanite 需实测收益）
- [ ] 面数：草 < 100 tri，灌木 < 5k，树 < 50k
- [ ] 贴图：2 的幂次，≤ 2048（植被 ≤ 1024）；仅 BaseColor/Emissive 开 sRGB；法线用 Normalmap 压缩；ORM 用 Masks 且关 sRGB
- [ ] 材质实例统一派生自花园母材质，不散落独立材质

我执行批量校验脚本，产出《入库报告》：命名违规、pivot 异常、超规格贴图、缺 LOD、材质未实例化清单。**全绿才进阶段⑥。**

## ⑥ 白盒（我）—— 从这里开始是你问的部分

**目标**：用灰模锁定**尺度、比例、动线、视线**，此时完全不碰美术资产。

我做的事：
1. 按需求单的尺寸，在 `L_Play`（或新关卡）搭出地面、高差、水体范围
2. 用 `SM_Cube / SM_Cylinder / SM_Ramp / SM_QuarterCylinder` 起量：围墙、亭子、花坛、树位、路径
3. 按动线摆**相机点位**，生成 4~6 张白盒截图
4. 输出《白盒说明》：每个模块的占位尺寸与坐标、玩家可行走范围、视线遮挡关系

**门禁 A：你要确认三件事**
1. 尺度对不对（人站进去是否会显得太大/太小）
2. 动线对不对（从入口走进去，视线引导是否如你所想）
3. 分区对不对（花坛、水景的位置要不要调）

> 为什么这一步不能跳：白盒阶段改一个尺寸只需 1 分钟，上装之后改要重摆上百个物体。

## ⑦ 上装（我）

**固定施工顺序**（顺序错了会反复返工）：

```
1. 地形定稿（高度、图层、地形材质）
2. 硬景结构（墙、台阶、路缘、驳岸）—— 用模块化件拼接，对齐网格
3. 建筑与道具（亭、椅、灯、花坛边）
4. 植被（乔木 → 灌木 → 地被 → 花卉），用植被工具 + 散布规则，不用手工一棵棵摆
5. 细节层（Decal 苔藓/污渍、碎石、落叶）
6. 特效（喷泉、花瓣、萤火虫、灯火）
7. 材质微调（材质实例参数：颜色、湿润度、风化度）
```

**材质绑定规则**：
- 只通过**材质实例**改外观，绝不直接改母材质
- 同一材质的多个变体走参数，不复制材质
- 湿润/风化/苔藓用参数或 Decal，不新建材质球

**我的自检**：每完成一个模块出一张截图，我自己先比对参考图，明显不符的先自己改一轮，再给你看。

## ⑧ 光照与氛围（我）

**硬约束**：`L_Play` 已存在 `BP_TimeManager` + `CF_FogColor` / `CF_SunColor` / `CF_SunIntensity`。

所以我的做法**不是新建一套光照**，而是：
1. 读取 `BP_TimeManager` 的驱动逻辑，让花园的光照参数接入现有曲线
2. 定向光接入 `CF_SunIntensity` / `CF_SunColor`，高度雾接入 `CF_FogColor`
3. 补天光、体积雾、后处理体积（曝光、Bloom、色温、暗角）
4. 给出**一天中 3 个时刻**的截图（晨/正午/黄昏）证明接入正常
5. 确认没有破坏其他关卡的既有表现

**门禁 B：你确认氛围方向** —— 我给 2~3 个氛围方案（清新 / 幽深 / 华丽），你选一个，我再精修。

## ⑨ 性能优化与 60fps 验证（我）

### 9.1 预算表（**待你确认后锁定**）

| 项目 | 建议目标（1080p / RTX 3060 档） | 状态 |
|---|---|---|
| 帧率 | 平均 ≥ 60，1% low ≥ 55 | 待确认 |
| 分辨率 | 1080p，TSR 100% | 待确认 |
| Draw Call | < 3500 | 待确认 |
| 可见三角面 | Nanite 场景可放宽；非 Nanite < 500 万 | 待确认 |
| 显存 | < 6 GB | 待确认 |
| 动态阴影距离 | ≤ 5000uu | 待确认 |
| 植被密度 | 单屏可见草丛实例 < 3 万 | 待确认 |

### 9.2 测试命令（可直接复制到控制台）

```
stat unit            帧时间总览（Game / Draw / GPU）
stat unitgraph       帧时间曲线，看 1% low 与卡顿
stat gpu             GPU 各阶段耗时
stat scenerendering  绘制调用、可见图元数
stat initviews       遮挡剔除效率
stat rhi             RHI 与显存
stat nanite          Nanite 集群与簇数
stat memory          内存占用
ProfileGPU           单帧 GPU 明细（在关卡里执行一次）
t.MaxFPS 60          锁定 60 帧，测试稳定性
stat startfile / stat stopfile  录制 Unreal Insights
```

### 9.3 测试方法

固定机位 + 固定飞行路线，录 60 秒，取 **平均帧时间** 与 **1% low**。只报平均帧率是耍流氓。

### 9.4 常见掉帧与对策

| 症状 | 对策 |
|---|---|
| 植被遮挡材质开销大 | 减密度、缩小遮罩面积、远处切 impostor |
| 动态阴影爆开销 | 限制投影阴影距离、远处植被关投影、静态物用 VSM 缓存 |
| Lumen 开销高 | 降 Lumen 质量档、限制 HW RT 距离、远处用屏幕追踪 |
| Draw Call 过高 | 合批、实例化、HLOD、Nanite |
| 半透明特效叠爆 | 限制同屏粒子数与 Overdraw |
